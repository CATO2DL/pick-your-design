# 跨轮状态、展示适配与示例

在开始视觉选型时读取本文件。这里规定状态和交互约定，不指定搜索服务或客户端；详细交付字段见 [design-spec-template.md](design-spec-template.md)。

## 最小跨轮状态

在会话或宿主提供的任务状态中保留以下信息即可，不需要数据库或独立应用。除非用户需要续接文件，不额外保存原始聊天。

| 状态 | 必要内容 |
| --- | --- |
| 项目与权限 | 用途、受众、媒介、输出格式、保存位置；仅规范/继续创作；发布授权是否存在 |
| 生图约束 | 选型零生图；最终创作是否允许生图；用户的其他限制 |
| 当前轮次 | 已完成轮数、本轮要回答的 1–2 个问题、下一可用编号 |
| 参考登记 | 永久编号、来源页面 URL、实际图像 URL 或截图位置、页面/裁切区域、访问日期、已查看/已显示状态 |
| 参考属性 | 可见特征；用户明确选中的属性；拒绝的属性与适用范围；待验证推断 |
| 决策 | 已确认偏好、排除项、锚点编号、待验证维度、反馈原意的简短摘要 |
| 内容与功能 | 已提供事实及来源、完整文案草稿、功能结果、缺失信息与设计建议 |
| 规范 | 文件位置、修订号、可执行/草案/受阻、未决问题及受影响章节 |

编号从 A、B…Z、AA…连续分配，或采用 R001、R002…；选一种后不混用。编号在整个任务内稳定。更换图像、截图时间版本或用于对比的裁切应获新编号，并记录与原图的关系。重新展示原锚点保留原编号和来源。

区分三类证据，例如：

- 用户明确要求：「采用 B 的左右分栏，颜色参考 E。」只确认布局与颜色。
- 已观察特征：「B 中左侧是大标题，右侧为人物照片。」前提是确实已查看图片。
- 待验证推断：「可能喜欢较低信息密度。」不得自动变成要求。

引用用户提供的尺寸时保留原值及单位；由 AI 补出的字号、断点、色值、比例等明确标为设计建议。不能从「喜欢暖色」推导出用户已确认某个 HEX 值。

## 展示适配

先识别「能搜索」「AI 能看图」「用户能看图」「能接收反馈」四种能力，不能用一种能力冒充另一种。

| 环境能力 | 展示方式与验证 |
| --- | --- |
| 原生图片搜索/图集 | 使用真实搜索结果，检查原图及来源；仅在图集支持稳定身份时绑定编号。结果未稳定时先等待或切换单图展示。 |
| Markdown 图片 | 使用宿主允许的图像地址或本地附件，逐张显示并附来源页；链接跳转成功不等于图像已渲染。 |
| 浏览器截图 | 打开有权访问的实际页面，截取相关区域，以用户可见图像输出；记录页面 URL、区域、视口与时间。截图不是网站成品。 |
| 自定义图集界面 | 卡片必须加载真实图像、稳定编号及来源；检查图片加载和反馈链路。点击不能回传时明确让用户在聊天中回复编号。不得用装饰卡片或渐变占位冒充参考图。 |
| 只有文本搜索 | 能收集来源但不能完成视觉选型。说明缺少显示/查看能力；转用允许的显示方式、用户参考，或经用户选择跳过并记录限制。 |

遵循宿主的图片展示与下载政策；不得通过下载、代理或重新托管绕过显示限制。图片失效时重新找可访问的来源，不画一张相似图片补位。

每张卡片按以下顺序呈现实际图像与文字，而不是把此文字结构当成展示完成：

1. 固定编号和实际渲染的图片。
2. 一句话描述它与同轮其他参考的可见区别。
3. 来源页面链接，以及必要的区域/版本说明。
4. 本轮关注的属性，例如「只比较构图，文案不作选择」。

用户反馈入口可直接写：「你可以回复 B，或 B 的布局 + E 的颜色，也可以只选一个局部、全部拒绝、回到旧图、补充参考，或跳过选型直接开始。」没有可用回传机制时不制作伪交互。

## 每轮转换

1. 搜索并检查候选，去除重复、不可见和差异不足的项。
2. 第一轮目标 6–7 张；后续默认 4–6 张总计，其中包含一个旧锚点和一个适度不同的探索项。用户指定数量优先；不足则如实少展示。
3. 展示并等待用户，不预设其选择。
4. 只更新反馈实际涉及的属性；保留其他确认项。
5. 明确方向后细化内容和功能，写规范。否则针对最重要的 1–2 个未知维度重新搜索。

如果没有选中任何参考，不虚构锚点；先找到拒绝原因。通常在 2–3 轮内结束视觉搜索；持续无进展则让用户决定下一步，而不是自动追加轮数。

## 交互示例

以下为工作流说明中的假设场景，不是实际搜索结果或已发生的用户反馈。执行时必须换成真实图像、来源与真实选择。

### 组合属性与回退

第一轮实际展示 A–G 后，用户说「B 的布局 + E 的颜色，B 的照片不要」。记录布局来源 B、配色来源 E、排除 B 的摄影；不能把 B 的字体和文案一并确认。

下一轮保留 B 作为布局锚点，新增 H–K，集中比较字体和摄影处理；其中 K 提供一个适度不同但保留布局要求的方向。新图不再叫 A–D。

用户说「都不喜欢」时，询问「是本轮 H–K 都不喜欢，还是也放弃之前 B 的布局、E 的颜色？」等待答复期间保留此前状态。若用户只拒绝 H–K，则不清空原偏好。

用户说「回到 E，但只保留背景色」时收窄 E 的借鉴范围；用户说「不用再选，直接写 MD」时停止搜索，用已知偏好和标明的设计建议写文件，不继续制作作品。

### 从风格到可执行要求

用户只说「留白多、读起来清楚」，不能写成其已确认 1200 px 宽度。可提出并记入规范：

| 参数 | 具体值 | 状态 | 依据 |
| --- | --- | --- | --- |
| 正文宽度 | 上限 68ch | 设计建议 | 限制单行长度，后续在实际文案上检查 |
| 主容器宽度 | 上限 1200 CSS px | 设计建议 | 为桌面留白提出的初值，非用户指定 |
| 正文 | 18 CSS px / 1.6 行高 | 设计建议 | 作为阅读版式的实现起点 |

这些是示例建议，不是所有项目的默认值；不能仅凭建议声称已通过可读性或无障碍验收。

### 缺失事实与只交 MD

用户要求活动海报规范但没有活动日期。先询问该事实；若用户要求先整理其余部分，实际保存草案，注明「活动日期未提供，禁止虚构；最终排版交付受阻」。可以给出具体布局与非事实文案建议，但不能留空标题大纲并宣布规范完整，也不能自行生图。

### 局部与全局变更

「只把按钮改成圆角」只改按钮半径及相应验收项，保持其他布局和文案。

「全局改成深色」检查全部背景、正文/次要文字、边框、状态色、图表、图像衬底、不同页面及导出版本，统一相关参数与对比检查项。正文删去旧浅色规范；修改记录保留旧值、替换原因、影响范围及待验证事项。

## 交付前检查

重新读取实际 `design-spec.md`：另一位 AI 能否仅凭此文件知道做什么、用什么内容、如何排版、交互结果、禁止做什么、哪些参数已确认、哪些是建议，以及如何验收？未解决的事实、许可或权限是否明确阻挡相应执行？

规范通过检查且已有创作授权才按其继续；只要用户要的是 MD，交付文件即结束。无文件工具或无法显示参考时分别报告实际能力缺口，不把文字描述称作已保存文件或已完成看图选择。
